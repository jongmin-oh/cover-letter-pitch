# cover-letter-pitch — 맞춤형 자기소개서/커버레터 작성 스킬

JD(채용공고)와 본인 경험을 입력하면, **직무 관련성·명료성·신뢰도를 높인 맞춤형 자기소개서 또는 영문 커버레터**를 작성하는 Claude / Claude Code 스킬입니다.

단순한 경력·기술 나열보다 **지원자가 어떤 문제를 발견하고 판단했으며, 그 결과 무엇이 달라졌는지**를 JD의 핵심 요구와 연결합니다. 모든 경험·수치는 사용자가 제공한 자료와 답변에서만 가져오며, 없는 내용은 지어내지 않습니다.

합격을 보장하거나 합격률을 예측하지는 않습니다. 대신 제출 문서의 관련성, 가독성, 사실성을 높이는 데 집중합니다.

## 무엇을 하나

```
JD 입력 + 후보자 경험
  └─► JD 분석 (Required/Preferred/Seniority/Context)
        └─► 제공된 경험 정리 → JD 매핑 → 핵심 증거 선택
              └─► 판단+임팩트 중심 문장 재작성
                    └─► 한국어 자소서 또는 영문 커버레터 작성
                          └─► 사실·형식·가독성 검증 → 제출용 본문 제공
```

- **JD 분석**: 필수/우대 역량, 시니어리티, 조직 맥락에 관한 단서를 파악
- **경험 매핑**: 제공된 경험을 직접성·증거 강도·희소성으로 정렬하고, 필요한 경우에만 누락된 핵심 경험을 추가 질문
- **어필 재작성**: "무엇을 했다"가 아니라 "왜 그 판단을 했고 결과가 무엇인가"로 변환
- **근거 검증**: 역할·기술·수치를 원본 자료와 대조하고, 확인되지 않은 수치는 정성적 결과로 교체
- **형식 분리**: 한국어 자소서와 영문 커버레터에 서로 다른 기본 분량과 구성을 적용
- **최소 질문**: 자료에서 알 수 있는 내용은 다시 묻지 않고, 결과에 영향을 주는 누락 정보만 한 번에 확인

## 설치

두 가지 방법 중 하나를 고르세요. **방법 1(스킬 디렉터리 클론)이 가장 간단**합니다.

### 방법 1 — 스킬 디렉터리에 클론 (권장)

레포를 스킬 폴더로 바로 클론합니다. 전역으로 쓰려면 `~/.claude/skills/` 아래에, 특정 프로젝트에만 쓰려면 그 프로젝트의 `.claude/skills/` 아래에 둡니다.

```bash
# 전역 설치 (모든 프로젝트에서 사용)
git clone https://github.com/jongmin-oh/cover-letter-pitch ~/.claude/skills/cover-letter-pitch

# 또는 특정 프로젝트에만
git clone https://github.com/jongmin-oh/cover-letter-pitch .claude/skills/cover-letter-pitch
```

다음 세션부터 자동 로드됩니다. `/cover-letter-pitch` 로 호출하거나, 그냥 "이 JD로 자기소개서 써줘"라고 요청하면 description 트리거로 자동 호출됩니다.

### 방법 2 — 플러그인으로 로컬 테스트

레포에 `.claude-plugin/plugin.json` 매니페스트가 있어 플러그인으로도 로드됩니다. 설치 없이 바로 띄워 테스트할 때 유용합니다.

```bash
# 레포를 클론한 위치에서
claude --plugin-dir /path/to/cover-letter-pitch
```

플러그인으로 로드하면 스킬이 네임스페이스로 호출됩니다 — `/cover-letter-pitch:cover-letter-pitch`. (정확한 이름은 `/help`에서 확인 가능합니다.)

### Claude (claude.ai)

`SKILL.md`를 커스텀 스킬/프로젝트 지침으로 등록하면 동일하게 동작합니다.

## 사용법

호출 시 다음 자료가 필요합니다.

**필수**
- JD 전문 (텍스트 / 파일 경로 / URL)
- 이력서 (파일 경로 또는 붙여넣은 텍스트)

**있으면 더 좋음**
- 포트폴리오 (이력서를 보완하는 자료 — PDF 파일 / 웹 링크 / 이미지 / 텍스트)
- 지원서 문항 (자유 양식 / 문항형)
- 글자 수·분량 제한
- 회사·제품 정보 (회사명, 제품, 최근 방향)
- 이력서 동봉 여부
- 목표 언어와 포지션 레벨 (자료에서 불분명한 경우)

> 이력서가 불릿만 있어 판단 이유·수치·임팩트가 부족하면, **핵심 경험에 대한 보강 질문 3~5개를 한 번에** 물어봅니다. 사용자가 초안 작성을 원하거나 정보를 모르면 합리적인 기본값으로 계속 진행합니다.

### 예시 프롬프트

```
아래 JD로 자기소개서를 써줘. 이력서는 resume.pdf, 포트폴리오는 https://my.portfolio 참고.
포지션 레벨: 미드 / 언어: 한국어
지원서 문항: 자유 양식 / 글자 수 제한: 1000자

[JD 전문]
...
```

> 포트폴리오는 선택입니다. 이력서만 줘도 동작하며, 부족한 근거는 작성 전 질문으로 채웁니다.

## 기본 작성 기준

사용자가 지정한 문항과 분량이 항상 우선합니다.

- **한국어 자유 양식**: 별도 제한이 없으면 공백 포함 800~1,200자
- **영문 커버레터**: 별도 제한이 없으면 250~400단어
- **핵심 경험**: 자유 양식에서는 일반적으로 가장 강한 2~3개
- **회사 과제 추론**: 공고에 충분한 단서가 있을 때만 가설형으로 사용
- **역량 공백**: 보유 경험처럼 꾸미지 않으며, 지정 문항 등 설명이 필요한 경우에만 언급

## 출력

제출용 본문을 먼저 채팅에 제공합니다. 사용자가 파일 저장을 요청하면 `cover-letters/{회사명}-{포지션}.md`에 저장합니다.

저장 파일에는 기본적으로 제출용 본문만 포함합니다. JD 분석이나 주장-근거표도 요청한 경우에는 `{회사명}-{포지션}-notes.md`로 분리합니다.

## 핵심 원칙

- 없는 경험·수치를 지어내지 않는다 (없으면 정성적 임팩트로 대체)
- 기술적 정확성을 가독성보다 낮게 두지 않는다
- 회사의 상황을 단정하지 않는다 — 충분한 단서가 있을 때만 가설형으로 표현
- 핵심 공백을 보유 경험처럼 쓰지 않되, 필요하지 않은 약점을 일괄적으로 먼저 나열하지 않는다
- "성실하고 열정적인"류의 빈 형용사보다 이를 증명하는 행동을 쓴다
- 사용자가 요구한 형식과 분량을 기본값보다 우선한다
