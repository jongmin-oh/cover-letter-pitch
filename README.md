# cover-letter-pitch — 맞춤형 자기소개서/커버레터 작성 스킬

JD(채용공고)와 본인 경험을 입력하면, **직무 관련성·명료성·신뢰도를 높인 맞춤형 자기소개서 또는 영문 커버레터**를 작성하는 Claude / Claude Code 스킬입니다.

단순한 경력·기술 나열보다 **지원자가 어떤 문제를 발견하고 판단했으며, 그 결과 무엇이 달라졌는지**를 JD의 핵심 요구와 연결하고, 최종적으로 **회사가 이 지원자를 뽑아야 하는 이유(WHY)**로 수렴시킵니다. 본문에 사용하는 모든 경험은 특정 JD 문구 또는 역할과 짝을 이루며, JD와 무관한 경력은 이력서에 있더라도 제외합니다. 모든 경험·수치는 사용자가 제공한 자료와 답변에서만 가져오며, 없는 내용은 지어내지 않습니다.

합격을 보장하거나 합격률을 예측하지는 않습니다. 대신 제출 문서의 관련성, 가독성, 사실성을 높이는 데 집중합니다.

## 무엇을 하나

```
JD 입력 + 후보자 경험
  └─► JD 분석 (Required/Preferred/Seniority/Context)
        └─► JD 주장 지도 작성 → 요구별 경험 매핑
              └─► 채용 이유(WHY) 한 문장 확정
                    └─► JD 앵커 → 경험 근거 → 입사 후 기여로 재작성
                          └─► 10블록 골격으로 한국어 자소서 / 영문 커버레터 작성
                                └─► 사실·채용 이유·형식·가독성 검증 → 제출용 본문 제공
```

- **JD 분석**: 필수/우대 역량, 시니어리티, 조직 맥락에 관한 단서를 파악
- **JD 주장 지도**: 핵심 JD 문구, 회사가 기대하는 행동, 관련 경험, 입사 후 기여를 먼저 짝지음
- **채용 이유 확정**: `회사의 과제 + 필요한 사람 + 지원자의 증거 + 회사가 얻는 것`을 한 문장으로 정리한 뒤 본문 작성 시작
- **경험 매핑**: JD와 직접 연결되는 경험만 직접성·증거 강도·희소성으로 정렬
- **어필 재작성**: "무엇을 했다"가 아니라 "이 경험이 왜 이번 JD의 증거이며 회사에 어떤 가치가 되는가"로 변환
- **검증된 골격 적용**: `정체성 선언 → 규모와 맥락 → JD 인용과 해석 → 같은 판단의 증거 → 기여 항목 2~3개 → 회사 연결 → 정직한 마무리`
- **실패 경험 활용**: JD와 관련된 시행착오를 숨기지 않고, 잘못된 가정·실패 신호·대응·남은 한계를 정직하게 서술
- **근거 검증**: 역할·기술·수치를 원본 자료와 대조하고, 확인되지 않은 수치는 정성적 결과로 교체
- **형식 분리**: 한국어 자소서와 영문 커버레터에 서로 다른 기본 분량과 구성을 적용
- **최소 질문**: 자료에서 알 수 있는 내용은 다시 묻지 않고, 결과에 영향을 주는 누락 정보만 한 번에 확인

## 설치

두 가지 방법 중 하나를 고르세요. **방법 1(스킬 디렉터리 클론)이 가장 간단**합니다.

### 방법 1 — 스킬 디렉터리에 클론 (권장)

레포를 스킬 폴더로 바로 클론합니다. 전역으로 쓰려면 `~/.claude/skills/` 아래에, 특정 프로젝트에만 쓰려면 그 프로젝트의 `.claude/skills/` 아래에 둡니다.

```bash
# 전역 설치 (모든 프로젝트에서 사용)
git clone https://github.com/jongmin-oh/cover-letter-pitch ~/.claude/skills/cover-letter-pitch

# 또는 특정 프로젝트에만
git clone https://github.com/jongmin-oh/cover-letter-pitch .claude/skills/cover-letter-pitch
```

다음 세션부터 자동 로드됩니다. `/cover-letter-pitch` 로 호출하거나, 그냥 "이 JD로 자기소개서 써줘"라고 요청하면 description 트리거로 자동 호출됩니다.

### 방법 2 — 플러그인으로 로컬 테스트

레포에 `.claude-plugin/plugin.json` 매니페스트가 있어 플러그인으로도 로드됩니다. 설치 없이 바로 띄워 테스트할 때 유용합니다.

```bash
# 레포를 클론한 위치에서
claude --plugin-dir /path/to/cover-letter-pitch
```

플러그인으로 로드하면 스킬이 네임스페이스로 호출됩니다 — `/cover-letter-pitch:cover-letter-pitch`. (정확한 이름은 `/help`에서 확인 가능합니다.)

### Claude (claude.ai)

`SKILL.md`를 커스텀 스킬/프로젝트 지침으로 등록하면 동일하게 동작합니다.

## 사용법

호출 시 다음 자료가 필요합니다.

**필수**
- JD 전문 (텍스트 / 파일 경로 / URL)
- 이력서 (파일 경로 또는 붙여넣은 텍스트)

**있으면 더 좋음**
- 포트폴리오 (이력서를 보완하는 자료 — PDF 파일 / 웹 링크 / 이미지 / 텍스트)
- 지원서 문항 (자유 양식 / 문항형)
- 글자 수·분량 제한
- 회사·제품 정보 (회사명, 제품, 최근 방향)
- 이력서 동봉 여부
- 목표 언어와 포지션 레벨 (자료에서 불분명한 경우)

> 이력서가 불릿만 있어 판단 이유·수치·임팩트가 부족하면, **핵심 경험에 대한 보강 질문 3~5개를 한 번에** 물어봅니다. 사용자가 초안 작성을 원하거나 정보를 모르면 합리적인 기본값으로 계속 진행합니다.

### 예시 프롬프트

```
아래 JD로 자기소개서를 써줘. 이력서는 resume.pdf, 포트폴리오는 https://my.portfolio 참고.
포지션 레벨: 미드 / 언어: 한국어
지원서 문항: 자유 양식 / 글자 수 제한: 1000자

[JD 전문]
...
```

> 포트폴리오는 선택입니다. 이력서만 줘도 동작하며, 부족한 근거는 작성 전 질문으로 채웁니다.

## 기본 작성 기준

사용자가 지정한 문항과 분량이 항상 우선합니다.

- **한국어 자유 양식**: 별도 제한이 없으면 공백 포함 1,500~2,300자 (10블록 골격 기준)
- **영문 커버레터**: 별도 제한이 없으면 250~400단어
- **핵심 경험**: 깊게 쓰는 판단 서사 1개 + 기여 항목 2~3개 (항목마다 근거 2~4개)
- **문체**: 볼드로 논지를 세우고, 기술명은 그 기술이 하던 역할로 풀어 쓰고, 숫자는 주장 뒤 근거 자리에
- **경험 채택 조건**: `JD 요구 → 관련 경험 → 입사 후 기여`를 모두 설명할 수 있어야 함
- **실패 경험**: 성공으로 끝나지 않았어도 판단, 대응, 위험 관리 능력을 보여준다면 활용
- **회사 과제 추론**: 공고에 충분한 단서가 있을 때만 가설형으로 사용
- **역량 공백**: 보유 경험처럼 꾸미지 않으며, 지정 문항 등 설명이 필요한 경우에만 언급
- **채용 이유**: 도입에서 왜 이 사람인지 드러내고, 각 단락이 그 이유를 부분 증명하며, 마무리에서 다시 선언
- **마무리**: `솔직한 공백 인정 → 극복 근거 → 당찬 기여 선언` 3박자. 공백은 하나만, 마지막 문장은 반드시 기여 선언

좋은 결과물은 경력을 시간순으로 요약하지 않습니다. JD의 핵심 문장에 반응하고, 같은 판단이나 역량을 보여준 과거 경험을 근거로 제시한 뒤, 지원 회사에서 재현할 기여로 연결합니다.

읽고 나서 "그래서 왜 이 사람인가"를 독자가 스스로 조립해야 하거나, "적합하다고 생각합니다" 수준의 선언에서 멈춘다면 채용 이유가 빠진 것으로 보고 다시 작성합니다.

다른 회사명과 포지션으로 바꿔도 그대로 사용할 수 있는 문단이라면 맞춤화에 실패한 것으로 보고 다시 작성합니다.

## 출력

제출용 본문을 먼저 채팅에 제공합니다. 사용자가 파일 저장을 요청하면 `cover-letters/{회사명}-{포지션}.md`에 저장합니다.

저장 파일에는 기본적으로 제출용 본문만 포함합니다. JD 분석이나 주장-근거표도 요청한 경우에는 `{회사명}-{포지션}-notes.md`로 분리합니다.

## 핵심 원칙

- 없는 경험·수치를 지어내지 않는다 (없으면 정성적 임팩트로 대체)
- 기술적 정확성을 가독성보다 낮게 두지 않는다
- 회사의 상황을 단정하지 않는다 — 충분한 단서가 있을 때만 가설형으로 표현
- 핵심 공백을 보유 경험처럼 쓰지 않되, 필요하지 않은 약점을 일괄적으로 먼저 나열하지 않는다
- 삽질과 실패를 숨기거나 억지 성공담으로 바꾸지 않는다
- 극복하지 못한 실패도 인정하되, 당시 판단·실패 신호·대응·남은 한계를 구체적으로 쓴다
- "성실하고 열정적인"류의 빈 형용사보다 이를 증명하는 행동을 쓴다
- 회사가 이 지원자를 뽑아야 하는 이유를 문장으로 드러낸다 — 경험 나열이나 적합성 선언으로 대신하지 않는다
- JD와 짝지을 수 없는 경험은 자기소개서에 넣지 않는다
- 이력서 문장을 옮기지 않고, 그 경험이 이번 JD에 왜 중요한지 해석한다
- JD 대비 공백은 마무리에서 한 번 솔직히 인정하되, 근거 있는 극복 방법을 함께 쓴다 (없는 약점은 지어내지 않는다)
- 마지막 문장은 지원 역할에서 책임질 행동과 만들 변화를 당차게 선언한다
- 사용자가 요구한 형식과 분량을 기본값보다 우선한다
